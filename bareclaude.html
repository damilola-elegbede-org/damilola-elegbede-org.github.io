BareClaude

A personal agentic operating system: a scheduled, budget-capped, audited AI chief of staff that runs finance, planning, legal, travel and ops work for one person, built and changed under the same controls I would expect on a production team.

Problem

I wanted an AI assistant that does recurring operational work without me prompting it, and I did not want to trust it blindly. Chat-only assistants forget context, have no schedule, and leave no audit trail. Agent frameworks that give a model broad credentials fail in the worst way: one bad run can message people, spend money, or merge code. The real problem was operating an unattended agent safely: bounded cost, bounded authority, visible failures, and changes that cannot silently break the thing running in production.

Architecture

BareClaude is a monorepo with three parts: an agent workspace (identity, rules, skills, schedules), shared infrastructure (queue, workers, health, release, lint), and a dashboard that shows fleet state.

Data flow. Triggers (schedules, chat messages, signed webhooks) never run the agent directly. Each one writes a work item to a per-agent queue. A long-running worker pool picks items up, checks the daily cost budget, prepends recent context, and starts a headless model session. The session reaches external systems only through identity wrappers. Results, logs and telemetry go to local state, and a health runner ingests them into the dashboard database.

Trust boundaries.

  1. Inbound: webhooks are signature-verified at a separate receiver process before anything is enqueued; chat is allowlisted.
  2. Agent to outside world: every call goes through a per-agent identity wrapper. The agent never uses my personal logins. Credentials are encrypted at rest and scoped per agent.
  3. Agent to code: the agent files requests; a human owns engineering implementation, review and merge.
  4. Production: the live checkout is production, so changes happen in isolated worktrees and pass lint and CI first.

Key design decisions

  1. Queue between every trigger and the agent. Triggers enqueue; workers run. Tradeoff: an added hop and more moving parts than calling the model from a cron job, in exchange for one place to enforce budgets, concurrency caps, context injection, retries and drain-on-shutdown. Every entry path gets the same controls.
  2. Identity wrappers instead of bare CLIs or broad tool servers. Agents call external services through thin per-agent scripts, not raw CLIs or general-purpose tool servers. Tradeoff: I maintain a wrapper per service and lose some convenience, but authority is narrow, auditable, and never borrows my own credentials.
  3. Human owns engineering, agent files requests. After running a fleet of specialist agents that wrote and merged code, I retired it. The agent now files deduplicated requests and a human implements, reviews and merges. Tradeoff: lower throughput on engineering tasks, higher trust and a clearer accountability line. The retirement was a recorded decision, not a quiet deletion.
  4. Lint rules as the memory of past incidents. Each recurring failure became a check rather than a note: 40 forbid-style lint rules run before merge. Tradeoff: more friction on every change, but lessons survive staff turnover, including the agent's own session turnover.
  5. No staging; production discipline instead. A single-person system does not justify a duplicate environment, so the live checkout is production, work happens in isolated worktrees, changes must pass a surface-impact review for shared files, and releases are built as immutable copies. Tradeoff: less safety than a real staging tier, mitigated by checks, recovery playbooks and tested backups.

Stack

  • Bun and TypeScript for long-running workers, health runner and chat listener
  • Node 22, Next.js 16, React 19, Tailwind v4 for the dashboard
  • SQLite for dashboard and telemetry storage
  • Bash and Python for wrappers, scripts and lint
  • Native OS scheduler for cron-style jobs
  • GitHub Actions for secret scanning, dashboard lint and test, webhook signature tests, infra tests
  • Claude Code headless sessions as the agent runtime; Codex used for independent review

Outcomes

  • 1,000+ merged pull requests in about 10 weeks (late July to early October 2026); the repo's PR numbering reaches 1,547 since it was created in early June.
  • 120 PRs merged in the last 9 days sampled, with a median of about 2.6 hours from open to merge across the most recent 1,000.
  • 35 written architecture and operations decision records, 22 operational playbooks, 40 automated lint rules.
  • About 740 test scripts in the repository, plus separate test suites for the workers, health runner and dashboard.
  • A failure taxonomy for agent runs (process failure, model-reported error, missing artifact, truncated result, timeout), so failures are classified rather than just logged.
